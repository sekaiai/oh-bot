# 长期陪伴系统实施依据

来源：用户提供的《oh-bot 多用户长期陪伴系统完整设计》v3.1，2026-10-21。
用户已要求继续实施，指定 Sol 主控拆解、集成和验收，Luna 编码、测试和修复。
原附件在云端环境恢复后已不在临时路径；本文件是已读取设计的实施约束摘要，不冒充原文副本。

## 产品与安全边界

一个统一成年角色南枝，稳定人格为温柔、主动表达、有主见、尊重空间；不推定性别外观，不默认猫系黏人。用户与角色为显式伴侣关系，其他人进入共同社交圈，不产生平行伴侣。管理员权限与社会关系分离。
身份以 personId 管理，经验证绑定平台，禁止昵称合并；角色、圈子、群聊、个人私聊、伴侣私密五类范围服务端先过滤再装配提示。来源区分说话者、所指人物、参与者、转述和亲历。共同实体不自动扩大披露权限。

## 固定技术与职责

Node.js 24 LTS、TypeScript、pnpm workspace；NestJS + Fastify；LangGraph.js 唯一对话/Agent 编排，生产 PostgreSQL checkpoint；LangChain 适配器经 ModelGateway 调用；Mem0 OSS TypeScript 唯一自动记忆引擎，经 MemoryGateway 访问；PostgreSQL + pgvector；Drizzle 业务表；pg-boss + business outbox；Vue3/Vite/Pinia/Element Plus 管理端；NapCat/OneBot 首期。
所有主聊天、记忆和向量计算经可配置第三方 API，不自行部署向量模型。不引入 AstrBot、第二套 AI SDK、第二个记忆提取器、Redis、独立向量库或图数据库。
Mem0 模型、过滤、pgvector、历史存储须核对锁定 SDK 的 OSS 实际能力，不能默认使用内存向量；SQLite 历史若不可替代，显式持久化卷和备份。第三方私有表由对应 SDK 迁移，不由业务 ORM 写入。

## 持久化和恢复

原文、来源、修订、删除日志和状态长期保存，索引可重建。更正立即使旧事实失效；删除同时处理原文/摘要/向量/缓存并在恢复旧备份后重放删除日志。关系和情绪基于有证据事件、版本校验，不随机增减，不惩罚忙碌/拒绝。
入站去重和 outbox 同事务。数据库租约不跨 LLM 长事务。发送状态区分失败和回执未知，恢复不能盲目重发。Mem0 至少一次调用+业务去重协调，不虚称恰好一次。
备份每6小时最近4份、每天30份、每周12份、每月36份；每日 restic 异机加密，每月隔离恢复，覆盖业务、Mem0、checkpoint、任务、媒体和必要配置。未配异机目标显示仅本机副本。
旧数据先备份迁移，旧好感仅 legacy；已截断历史不伪造。新系统验收前不删除旧源码/数据。不实际部署、不注册供应商、不创建凭据、不发真实 QQ 消息。

## 编排和工具

identity → context → memory → route → tool/agent → compose → deliver → finalize。普通聊天短路径；工具/子图输出结构化结果，唯一角色统一表达。权限、预算、超时、取消传播与外部动作回执统一服务端约束。外部资料不可信。主动联系默认关闭，提醒必须持久化并确定时间。

## 实施顺序和验收

1. 锁定并实测 Mem0 Node + pgvector + 第三方 embeddings + LangGraph PG checkpoint。
2. 数据、身份、权限、任务、备份与旧数据迁移。
3. QQ 与 LangGraph 对话短路径。
4. Mem0 来源校验、更正、删除与长期检索。
5. 统一人格、社交圈、多用户关系及伴侣关系。
6. 工具与 Agent 注册中心、旧工具迁移、搜索能力预留。
7. 管理端、故障恢复、至少50个固定对话/故障场景验收。

阶段是执行顺序，不意味着缩减首版。外部 API 未配置必须报告不可用，不能以测试替身通过代替第三方真实能力通过。先完成可审查的兼容性门禁，若锁定组合或外部条件不满足则阻止破坏性迁移，保留明确可恢复记录。
