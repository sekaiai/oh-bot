# oh-bot MVP 交付路线（2026-10-23）

## 目标与交付口径

优先交付**能实际对话**的最小闭环，而不是先做完整自动化平台或全部管理页面。MVP 验收依次为：
1. **本地可对话**：在开发环境显式配置聊天模型 API 后，用本地 CLI 发出消息并收到真实模型回答；没有业务聊天凭据时应明确报“未配置”，不能把自动编码 API 的测试当作聊天验收。
2. **有身份、有历史**：同一可信身份的多轮对话有可持久化历史；不同用户不串话，不允许仅凭自报用户 ID 越权访问别人的历史。
3. **有人格、有关系**：核心人格稳定；机器人对不同人的关系状态分别持久化；主伴侣身份须经过可信绑定，不能由任意请求指定。
4. **有记忆**：只召回经过来源验证且有权限读取的记忆；更正/遗忘后旧事实不再进入提示；写入失败可降级为无记忆聊天，不能泄漏其他人的记忆。
5. **有可选渠道**：NapCat/OneBot 在显式开启且配置后可收发，重复消息幂等，回执未知不盲目重发；无 QQ 凭据可先用本地 CLI 验收。
6. **有验收证据**：分别记录离线测试、隔离 PostgreSQL 测试、真实模型测试和真实 QQ 测试；不能用 fixture 冒充在线通过。

## 执行规则

- `docs/implementation/unattended-tasks.md` 中的 M 系列任务优先于旧 F 系列剩余任务；每轮只完成一个 M 任务，控制器负责提交和复审。
- 优先复用现有 F1-F4 数据库、身份、ACL、worker、记忆账本；不要重写已有模块，不要切换生产运行路径。
- 不新增复杂 Agent/搜索、完整管理后台、自动部署平台，直到本地对话 MVP 有可验证交付。
- 隐私隔离、凭据保护、来源核验、幂等、删除/更正的安全边界**不可为了加速而跳过**。不具备可信身份时仅允许明确的单用户本地开发沙盒，不对外暴露无鉴权聊天接口。
- 当前编码与审查模型的 GitHub Actions Secrets **不自动用于业务聊天**；业务聊天凭据须单独配置。缺少业务聊天凭据时可以完成协议/隔离测试，但不能宣称真实模型对话已通过。
- 每个任务完成后在 `docs/implementation/progress.md` 记录：交付入口、如何本地运行、已运行测试、未配置的外部依赖和下一步。真实结果由可信工作流记录。
- M 系列完成后恢复剩余 F 系列，先检查是否已被 M 系列覆盖，避免重复实现；没有通过验收的旧任务不得直接标记完成。

## 阶段性可用成果

| 阶段 | 用户能做什么 | 验收 |
| --- | --- | --- |
| M1a | 本地终端发消息，获得真实聊天模型响应（配置后） | CLI 与协议 fixture；有凭据时真实调用 |
| M1b | 可信用户的多轮会话，隔离历史 | 真实 PG 并发/越权回归 |
| M2a | 感受到稳定人格和按用户独立关系 | 重启后持久化，越权不可改主伴侣 |
| M2b | 机器人记得且能纠正/忘记 | ACL/修订/删除/故障降级回归 |
| M3a | 在 QQ 中对话（可选渠道） | OneBot fixture；live 需要用户渠道配置 |
| M3b | 一键启动本地 MVP 并明确哪些 live 门禁未过 | 构建、测试、手工体验说明 |
